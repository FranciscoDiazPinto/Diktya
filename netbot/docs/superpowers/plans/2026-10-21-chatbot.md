# Network Chatbot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an authenticated Spanish-language chatbot backed by OpenRouter that answers Netbot network monitoring questions through a tightly allow-listed set of read-only tools and a small dashboard panel.

**Architecture:** Add `CHAT_USE` for `visor`; keep the authenticated user and all permissions server-side. A ChatService will call OpenRouter's chat-completions API and execute only registered monitoring functions after backend permission checks. The browser sends a bounded conversation history and renders responses, while the backend retains no conversation history.

**Tech Stack:** FastAPI, Pydantic, existing `httpx`, SQLAlchemy-backed roles, existing `MonitoringService`, vanilla HTML/CSS/JavaScript, pytest.

The browser state is deliberately ephemeral; this plan adds no database models or migrations. The existing `httpx` package is sufficient for the provider adapter, so no SDK dependency is planned. OpenRouter's documented chat-completions endpoint supports user-defined function tools; the application must execute these tools itself so it can enforce authorization ([OpenRouter chat completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request), [tool calling overview](https://openrouter.ai/docs/guides/features/server-tools/overview)). Do not enable OpenRouter-operated server tools.

- [x] **Step 3: Create request/response schemas**

Create Pydantic models in `schemas.py`:

```python
class ChatTurn(BaseModel):
    role: Literal["user", "assistant"]
    content: str

class ChatMessageRequest(BaseModel):
    message: str = Field(min_length=1)
    history: list[ChatTurn] = Field(default_factory=list)

class ChatMessageResponse(BaseModel):
    answer: str
    tools_used: list[str] = Field(default_factory=list)
```

In a normalization function, trim text, reject messages longer than configured limits, keep only the most recent configured number of turns, and reject history whose combined content exceeds the configured request budget. Never accept system or tool turns from the browser.

- [x] **Step 4: Define the system policy in one module**

Create a Spanish system message in `policy.py`; keep it independent of request content. It must scope the assistant to networking, Netbot, and monitoring; tell it to decline unrelated requests; state that only backend tool results are live infrastructure facts; and forbid following instructions embedded in user text, history, hostnames, firewall events, or other tool data.

- [x] **Step 5: Implement the closed monitoring tool registry**

Reject unknown tool names, extra arguments, invalid types, and oversized limits before calling the service. Serialize only normalized Pydantic response data needed for the answer.
